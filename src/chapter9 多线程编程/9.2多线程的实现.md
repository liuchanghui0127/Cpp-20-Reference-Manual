## **9.2多线程的实现**

通过原子操作和互斥体可以实现线程的同步

### **9.2.1原子操作库**

原子类型支持原子访问，定义在<atomic>中，所有基本类型都有对应的整型原子类型，声明示例如下：
```
atomic<int> counter{0};
```
整形原子类型支持以下原子操作：fetch_add()、fetch_sub()、fetch_and()、fetch_or()、fetch_xor()、++、--、+=、-=、&=、^=和|=

原子指针类型支持fetch_add()、fetch_sub、++、--、+=、-=

#### **C++20原子操作新特性**

C++20引入了原子智能指针atomic<std::shared_ptr<T>>，可以解决多个线程使用同一个shared_ptr的冲突问题，原子智能指针是完全线程安全的。

C++20也引入了原子引用std::atomic_ref，其与atomic基本相同，但使用的是引用。

C++20增加了一些方法用于等待原子变量被修改，如下所示：

wait(oldValue):阻塞进程，直到另一个线程调用notify_one()或notify_all()并且原子变量的值已经改变，即不等于oldValue；

notify_one():唤醒一个阻塞在wait()上的线程；

notify_all():唤醒所有阻塞在wait()上的线程。

使用示例如下所示：
```
import <thread>;
import <atomic>;
import <iostream>;
import <chrono>;
using namespace std;
int main()
{
	atomic<int> value{ 0 };
	thread job{ [&value] {
		cout << "Thread starts waiting." << endl;
		value.wait(0);
		cout << "Thread wakes up, value = " << value << endl;
	} };
	this_thread::sleep_for(2s);
	cout << "Main thread is going to change value to 1." << endl;
	value = 1;
	value.notify_all();
	job.join();
}
```
### **9.2.2互斥**
在设计多线程程序时，如果不能避免数据共享，那么就必须提供同步机制，对于数据复杂的情况，通常使用互斥体类或者锁类实现线程之间的同步。

### **9.2.2.1互斥体类**
C++提供了非定时和定时的互斥体类，且又分为递归和非递归类型。

1、非定时的互斥体类
标准库有3个非定时的互斥体类：std::mutex、std::recursive_mutex和shared_mutex,每个类都支持下列方法：

lock():线程尝试获取锁，并阻塞直到获得锁

try_lock():线程尝试获取锁，获取成功返回true，否则返回false

unlock():释放由调用线程持有的锁

sd::mutex：只能有一个线程拥有互斥体，已经拥有mutex所有权的线程不能在这个互斥体上再次调用lock或try_lock

std::recursive_mutex：和mutex几乎一致，区别在于已经获得递归互斥体所有权的线程允许在同一个互斥体上再次调用lock和try_lock,调用线程调用unlock的次数应该等于上锁次数

shared_mutex：线程可获取锁的独占所有权或共享所有权，独占所有权仅当没有其他线程拥有独占或共享所有权时才能获得，共享所有权仅当其他线程没有独占所有权时才可获得，
其还具有与共享所有权相关的方法：lock_shared()try_lock_shared()unlock_shared()

2、定时的互斥体类
标准库提供了3个定时的互斥体类：std::timed_mutex、std::recursive_timed_mutex和shared_timed_mutex,这些类与前述非定时互斥体所支持的方法类似

此外还支持以下方法用于定时获取：

try_lock_for(rel_time):调用线程尝试在给定的相对时间内获取锁，如果在超时之前获得锁则返回true，并将超时时间指定为std::chrono::duration，否则返回false

try_lock_until(abs_time):调用线程尝试在给定的绝对时间内获取锁，如果在超时之前获得锁则返回true，并将超时时间指定为std::chrono::time_point，否则返回false
### **9.2.2.2锁类**
C++标准定义了4种类型的锁：std::lock_guard、unique_lock、shared_lock、scope_lock

1、std::lock_guard

lock_guard定义在<mutex>,有2个构造函数

explicit lock_guard(mutex_type& m);这个构造函数尝试获得互斥体上的锁，并阻塞直到获得锁

lock_guard(mutex_type& m,adopt_lock_t);C++提供一个预定义的adopt_lock_t实例，该锁假定调用线程已经获得引用的互斥体上的锁，管理该锁，在销毁锁时自动释放互斥体

2、std::unique_lock
unique_lock定义在<mutex>,允许将获得锁的时间延迟到计算需要时，有6个构造函数，如下所示：

explicit unique_lock(mutex_type& m);这个构造函数尝试获得互斥体上的锁，并阻塞直到获得锁

unique_lock(mutex_type& m,defer_lock_t)noexcept;C++提供一个预定义的defer_lock_t实例，unique_lock存储互斥体的引用，但不立即尝试获得锁，锁可以稍后获得

unique_lock(mutex_type& m,try_to_lock_t);C++提供一个预定义的try_to_lock_t实例，这个锁尝试获得引用的互斥体上的锁，但未获得也不阻塞，会在稍后获取锁

unique_lock(mutex_type& m,adopt_lock_t);C++提供一个预定义的adopt_lock_t实例，这个锁假定调用线程已经获得引用的互斥体上的锁，锁管理互斥体并在销毁锁时自动释放互斥体

unique_lock(mutex_type& m,const chrono::time_point<Clock,Duration>& abs_time);这个锁尝试获得引用的互斥体上的锁，直到系统时间超过给定的绝对时间

unique_lock(mutex_type& m,const chrono::time_point<Rep,Period>& rel_time);这个锁尝试获得引用的互斥体上的锁，直到系统时间超过给定的相对超时时间

3、shared_lock

shared_lock在<shared_mutex>中定义，它的构造函数和方法与unique_lock相同，区别是在共享互斥体上调用与共享拥有权相关的方法lock_shared()、try_lock_shared()等

4、scope_lock

scope_lock在<mutex>中定义，与local_guard相似，但可以接收数量可变的互斥体

使用示例演示如何使用定时的互斥体，如下所示：
```
import <thread>;
import <iostream>;
import <mutex>;
import <chrono>;

using namespace std;

class Counter
{
public:
	Counter(int id, int numIterations)
		: m_id{ id }, m_numIterations{ numIterations }
	{
	}

	void operator()() const
	{
		for (int i{ 0 }; i < m_numIterations; ++i) {
			unique_lock lock{ ms_timedMutex, 200ms };
			if (lock) {
				cout << "Counter " << m_id << " has value " << i << endl;
			} else {
				// Lock not acquired in 200ms, skip output.
			}
		}
	}

private:
	int m_id;
	int m_numIterations;
	inline static timed_mutex ms_timedMutex;
};

int main()
{
	thread t1{ Counter{ 1, 20 } };
	Counter c{ 2, 12 };
	thread t2{ c };
	t1.join();
	t2.join();
}

```
该示例使用unique_lock结合timed_mutex,试图在200毫秒内获得一个锁，通过检查是否获得锁决定是否进行输出
